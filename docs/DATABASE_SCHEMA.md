# Database Schema Documentation

## Overview

Geriacare uses PostgreSQL with Drizzle ORM for type-safe database access. The schema is structured around content (posts), users, signals (votes/endorsements), and authentication.

**File Location**: `src/db/schema.ts`

**Connection**: Powered by Neon PostgreSQL via `postgres` client

## Core Enumerations

### Role Enum

```sql
type "role" = 'family' | 'expert' | 'moderator'
```

| Value | Meaning |
|-------|---------|
| `family` | Default - regular user asking/answering questions |
| `expert` | Verified professional (doctor/nurse/therapist) |
| `moderator` | Can review content, manage users, publish articles |

### Post Type Enum

```sql
type "post_type" = 'question' | 'article' | 'answer' | 'comment'
```

| Value | Meaning |
|-------|---------|
| `question` | User-submitted elder care question |
| `article` | Care guide/tip (expert-only) |
| `answer` | Response to a question |
| `comment` | Clarification on an answer (no voting) |

### Post Status Enum

```sql
type "post_status" = 'live' | 'needs_review' | 'hidden' | 'closed'
```

| Value | Visibility | Triggered By |
|-------|-----------|--------------|
| `live` | Public feed | Approved content |
| `needs_review` | Hidden | Crisis language OR first-time poster |
| `hidden` | Hidden | 2+ community flags OR moderator action |
| `closed` | Public (read-only) | Question resolved/moderator decision |

### Vote Kind Enum

```sql
type "vote_kind" = 'helpful' | 'unclear'
```

Users can vote on answers:
- `helpful`: Found this answer useful
- `unclear`: This answer is confusing

### Urgency Enum

```sql
type "urgency" = 'low' | 'normal' | 'high' | 'emergency'
```

Set by question asker to indicate severity of situation.

## Tables

### users

Stores user accounts and authentication data.

```sql
CREATE TABLE "user" (
  id TEXT PRIMARY KEY,
  name TEXT,
  email TEXT UNIQUE,
  emailVerified TIMESTAMP,
  image TEXT,
  
  role "role" NOT NULL DEFAULT 'family',
  bio TEXT,
  specialization TEXT,                -- For experts: 'Geriatric Medicine', etc.
  city TEXT,
  
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

**Fields**:

| Field | Type | Notes |
|-------|------|-------|
| `id` | TEXT | UUID, generated by crypto.randomUUID() |
| `name` | TEXT | User's display name from Google/OAuth |
| `email` | TEXT | Unique, from Google/OAuth |
| `emailVerified` | TIMESTAMP | When email was verified (OAuth) |
| `image` | TEXT | Avatar URL from Google |
| `role` | role enum | 'family' \| 'expert' \| 'moderator' |
| `bio` | TEXT | User bio (for experts) |
| `specialization` | TEXT | Medical specialty (e.g. "Nurse Practitioner") |
| `city` | TEXT | User location |
| `created_at` | TIMESTAMP | Account creation time |

**Queries**:
```typescript
// Get user by email
await db.select().from(users).where(eq(users.email, email));

// Get all experts in a city
await db.select().from(users)
  .where(and(eq(users.role, "expert"), eq(users.city, city)));

// Promote user to expert
await db.update(users)
  .set({ role: "expert", specialization: "Geriatric Nurse" })
  .where(eq(users.id, userId));
```

### posts

The core content table for all posts (questions, answers, articles, comments).

```sql
CREATE TABLE "post" (
  id TEXT PRIMARY KEY,
  type "post_type" NOT NULL,
  author_id TEXT REFERENCES "user" ON DELETE CASCADE,
  author_name TEXT,                   -- Anonymous author name
  
  title TEXT,
  body TEXT NOT NULL,
  slug TEXT UNIQUE,
  parent_id TEXT,                     -- For answers/comments: parent post
  
  status "post_status" NOT NULL DEFAULT 'live',
  crisis_flagged_at TIMESTAMP,        -- When crisis was detected
  
  helpful_count INT NOT NULL DEFAULT 0,
  answer_count INT NOT NULL DEFAULT 0,
  flag_count INT NOT NULL DEFAULT 0,
  
  -- Geriatric context (questions only)
  patient_age INT,
  patient_gender TEXT,
  condition TEXT,
  medications TEXT,
  city TEXT,
  urgency "urgency" NOT NULL DEFAULT 'normal',
  care_setting TEXT,
  relation TEXT,
  
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  edited_at TIMESTAMP,
  
  INDEX post_parent_idx ON (parent_id),
  INDEX post_feed_idx ON (type, status, created_at),
  UNIQUE INDEX post_slug_idx ON (slug)
);
```

**Fields**:

| Field | Type | Notes |
|-------|------|-------|
| `id` | TEXT | UUID |
| `type` | enum | question \| article \| answer \| comment |
| `author_id` | TEXT | FK to users, NULL if anonymous |
| `author_name` | TEXT | Name if anonymous posting |
| `title` | TEXT | Question/article title |
| `body` | TEXT | Full post content |
| `slug` | TEXT | URL slug (title-random5chars) |
| `parent_id` | TEXT | FK to post if answer/comment |
| `status` | enum | live \| needs_review \| hidden \| closed |
| `crisis_flagged_at` | TIMESTAMP | Timestamp crisis detected |
| `helpful_count` | INT | Votes for "helpful" |
| `answer_count` | INT | # of answers to this question |
| `flag_count` | INT | # of community flags |
| `patient_age` | INT | Age of elder (questions) |
| `patient_gender` | TEXT | 'male' \| 'female' \| 'other' |
| `condition` | TEXT | Diagnosis/condition description |
| `medications` | TEXT | Current medications list |
| `city` | TEXT | Patient location |
| `urgency` | enum | low \| normal \| high \| emergency |
| `care_setting` | TEXT | home \| hospital \| assisted_living \| rehab |
| `relation` | TEXT | son \| daughter \| spouse \| self \| caregiver |
| `created_at` | TIMESTAMP | When posted |
| `edited_at` | TIMESTAMP | When last edited |

**Queries**:
```typescript
// Create a question
await db.insert(posts).values({
  type: "question",
  authorId: user.id,
  title: "My mother won't eat",
  body: "Situation: ...",
  slug: slugify(title),
  status: "live",
  patientAge: 78,
  urgency: "high"
}).returning();

// Get feed (live posts, ordered by date)
await db.select().from(posts)
  .where(and(eq(posts.type, "question"), eq(posts.status, "live")))
  .orderBy(desc(posts.createdAt))
  .limit(20);

// Get answers to a question
await db.select().from(posts)
  .where(and(eq(posts.parentId, questionId), eq(posts.type, "answer")))
  .orderBy(desc(posts.helpfulCount));

// Get posts needing review
await db.select().from(posts)
  .where(eq(posts.status, "needs_review"));
```

### votes

Records helpful/unclear votes on answers.

```sql
CREATE TABLE "vote" (
  user_id TEXT NOT NULL REFERENCES "user" ON DELETE CASCADE,
  post_id TEXT NOT NULL REFERENCES "post" ON DELETE CASCADE,
  kind "vote_kind" NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  
  PRIMARY KEY (user_id, post_id)
);
```

**Design**: Composite key (one vote per user per post). Only one vote per user, not multiple votes on same post.

**Queries**:
```typescript
// Vote on a post
await db.insert(votes).values({
  userId: user.id,
  postId: post.id,
  kind: "helpful"
}).onConflictDoUpdate({
  target: [votes.userId, votes.postId],
  set: { kind: "helpful" }
});

// Get vote counts
await db.select({ kind: votes.kind, count: count() })
  .from(votes)
  .where(eq(votes.postId, postId))
  .groupBy(votes.kind);
```

### endorsements

Expert endorsements of answer quality.

```sql
CREATE TABLE "endorsement" (
  post_id TEXT NOT NULL REFERENCES "post" ON DELETE CASCADE,
  expert_id TEXT NOT NULL REFERENCES "user" ON DELETE CASCADE,
  note TEXT,                          -- Endorsement reason
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  
  PRIMARY KEY (post_id, expert_id)
);
```

**Design**: One endorsement per expert per post.

**Queries**:
```typescript
// Endorse an answer
await db.insert(endorsements).values({
  postId: answerId,
  expertId: expert.id,
  note: "This is medically accurate approach"
});

// Get endorsements for a post
await db.select().from(endorsements)
  .where(eq(endorsements.postId, answerId));
```

### flags

Community flags reporting inappropriate/dangerous content.

```sql
CREATE TABLE "flag" (
  id TEXT PRIMARY KEY,
  post_id TEXT NOT NULL REFERENCES "post" ON DELETE CASCADE,
  reporter_id TEXT REFERENCES "user" ON DELETE CASCADE,
  reporter_key TEXT NOT NULL,        -- Anonymous or user ID
  reason TEXT NOT NULL,
  resolved_at TIMESTAMP,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  
  UNIQUE INDEX flag_once_idx ON (post_id, reporter_key)
);
```

**Design**: One flag per user/anonymous reporter per post (no duplicate flags).

**Queries**:
```typescript
// Flag a post
await db.insert(flags).values({
  postId: post.id,
  reporterId: user?.id ?? null,
  reporterKey: anonymousKey,
  reason: "Harmful medical advice"
});

// Count flags on a post
const [result] = await db.select({ count: count() })
  .from(flags)
  .where(eq(flags.postId, postId));

// Auto-hide if 2+ flags
if (result.count >= 2) {
  await db.update(posts)
    .set({ status: "hidden" })
    .where(eq(posts.id, postId));
}

// Get flagged posts for moderation
await db.select().from(posts)
  .where(eq(posts.flagCount, sql`<> 0`))
  .orderBy(desc(posts.flagCount));
```

### postTags

Junction table linking posts to tags.

```sql
CREATE TABLE "post_tag" (
  post_id TEXT NOT NULL REFERENCES "post" ON DELETE CASCADE,
  tag_id TEXT NOT NULL REFERENCES "tag" ON DELETE CASCADE,
  
  PRIMARY KEY (post_id, tag_id)
);
```

**Queries**:
```typescript
// Get posts with a tag
await db.select().from(posts)
  .innerJoin(postTags, eq(posts.id, postTags.postId))
  .where(eq(postTags.tagId, tagId));

// Add tags to post
const tagRows = await db.select().from(tags)
  .where(inArray(tags.slug, ["dementia", "diet"]));

await db.insert(postTags).values(
  tagRows.map(tag => ({ postId: post.id, tagId: tag.id }))
);
```

## Indexing Strategy

### Indexes (Query Performance)

| Table | Index | Purpose |
|-------|-------|---------|
| posts | `post_parent_idx` | Find answers/comments by parent |
| posts | `post_feed_idx` | Efficient feed queries (type, status, created_at) |
| posts | `post_slug_idx` | URL slug lookups (unique) |
| flags | `flag_once_idx` | Prevent duplicate flags |
| users | `email` (unique) | OAuth lookups |
| posts | `author_id` (FK) | Find user's posts |

### Query Patterns

**Feed Query** (most common):
```sql
SELECT * FROM post 
WHERE type = 'question' AND status = 'live'
ORDER BY created_at DESC
LIMIT 20;
-- Uses: post_feed_idx (type, status, created_at)
```

**Thread Query**:
```sql
SELECT * FROM post WHERE parent_id = $1
-- Uses: post_parent_idx
```

## Relationships

```
users (1) --←-- (many) posts (via author_id)
users (1) --←-- (many) votes (via user_id)
users (1) --←-- (many) endorsements (via expert_id)

posts (1) --←-- (many) posts (parent → answers via parent_id)
posts (1) --←-- (many) votes (via post_id)
posts (1) --←-- (many) endorsements (via post_id)
posts (1) --←-- (many) flags (via post_id)
posts (1) --←-- (many) postTags (via post_id)

tags (1) --←-- (many) postTags (via tag_id)
```

## Cascade Behavior

Most foreign keys use `ON DELETE CASCADE`:
- Delete user → Delete their posts, votes, endorsements
- Delete post → Delete comments, votes, flags, tags

This keeps the database clean when content is removed.

## Example Queries

### Create Question with Tags

```typescript
const [post] = await db
  .insert(posts)
  .values({
    type: "question",
    authorId: user.id,
    title: "Mother won't eat",
    body: "Situation...",
    slug: slugify(title),
    status: "live",
    patientAge: 78,
    urgency: "high"
  })
  .returning();

const tags = await db.select().from(tags)
  .where(inArray(tags.slug, ["appetite-loss", "nutrition"]));

await db.insert(postTags).values(
  tags.map(t => ({ postId: post.id, tagId: t.id }))
);
```

### Get Question Thread

```typescript
const question = await db.select().from(posts)
  .where(and(eq(posts.id, id), eq(posts.type, "question")))
  .then(r => r[0]);

const answers = await db.select()
  .from(posts)
  .where(and(eq(posts.parentId, id), eq(posts.type, "answer")))
  .orderBy(desc(posts.helpfulCount));

const answerIds = answers.map(a => a.id);

const comments = answerIds.length ? 
  await db.select().from(posts)
    .where(and(inArray(posts.parentId, answerIds), eq(posts.type, "comment")))
  : [];

return { question, answers, comments };
```

### Crisis Detection to Publishing

```typescript
const body = `**Situation**\n\n${situation}`;
const needsReview = detectCrisis(body);

const [post] = await db.insert(posts)
  .values({
    type: "question",
    body,
    status: needsReview ? "needs_review" : "live",
    crisisFlagged: needsReview ? new Date() : null
  })
  .returning();
```

## Performance Tips

1. **Pagination**: Always use LIMIT to avoid loading all posts
2. **Indexes**: Use indexed fields in WHERE clauses
3. **Joins**: Minimize joins (posts table is denormalized for speed)
4. **Caching**: Page paths are revalidated on writes
5. **Batch**: Insert multiple tags in one transaction

## Data Integrity

- **Type Safety**: Drizzle ORM ensures correct types
- **Constraints**: Unique indexes prevent duplicates
- **Foreign Keys**: Referential integrity via CASCADE
- **Enums**: Database-level enums prevent invalid values

## Migrations

Schema changes use Drizzle Kit:

```bash
npm run db:push        # Apply pending migrations
drizzle-kit generate  # Generate migration files
```

Do NOT modify schema.ts manually - changes must be reflected in database.

## Backup & Recovery

PostgreSQL backups should be:
- Daily snapshots (via Neon)
- Point-in-time recovery enabled
- Tested restoration procedures
- Retention: 30+ days
